# PULSE: YouTube check timeout, loud errors, check-all progress

## Goal
Stack-wide AI-ops-UX retrofit (4 of 4, after BLAST/HOOKLAB/RECALL). PULSE has
no AI calls, so no thinking toggle and no timer helper — its leg is the same
reliability discipline applied to the YouTube stats checker: a request
timeout so one hung fetch can't stall the check-all loop forever, errors that
are always visible instead of silently swallowed on quiet auto-checks, and
per-post progress on manual check-all.

## Facts
- fetchYouTubeStats had NO timeout: a hung request stalled autoCheckDue's
  sequential loop with no way to recover.
- checkYouTube's catch only toasted when opts.loud — the startup auto-check
  swallowed every failure, so a bad key or dead network looked identical to
  "nothing due".
- toast() had a fixed 2.6s duration — too short for a failure summary the
  user is supposed to actually read.

## Changes (app.js only)
- toast(msg, ms): optional duration, default unchanged (2600).
- fetchWithTimeout(url, ms) + YT_TIMEOUT_MS 15000, applied per attempt inside
  the existing fetchWithRetry; abort surfaces as "YouTube request timed out —
  check your connection and try again".
- checkYouTube catch: ALWAYS console.error + store lastCheckError; loud →
  6s toast.
- autoCheckDue: "Checking i/N…" progress toasts when loud; summary
  "K updated, F failed: <lastCheckError>" (6s) whenever anything failed —
  including the quiet startup check; success summary stays loud-only.
